# Banco de dados: PostgreSQL e modelagem

## 1. Onde fica

- **PostgreSQL 15+**: Supabase (equipe) ou container do `docker-compose` (local).
- Scripts em `Data/Modelagem`:
  - `GastroDB_v2.0.0_postgres.sql`: schema principal.
  - `GastroDB_v2.1.0_restaurante_localizacao.sql`: localização do restaurante.
  - `GastroDB_dados_exemplo.sql`: dados de teste.
  - `legado-mysql/`: versão antiga (MySQL v1.0.0), só histórico.
- Passo a passo para rodar: `Backend/SETUP-BANCO.md`.

## 2. Tabelas

| Tabela | Papel |
|---|---|
| `usuario` | Conta de login (email, username, hash) |
| `refresh_token` | Sessões (hash SHA-256 do token) |
| `profissional` | Tabela mãe de chef, nutricionista e restaurante |
| `chef`, `nutricionista`, `restaurante` | Perfis profissionais |
| `receita` | Receita publicada por um chef |
| `etapa_receita` | Passos da receita, com `ordem` |
| `dica` | Dica ou erro comum, ligada a uma etapa e a um chef |
| `ingrediente` | Catálogo com valores nutricionais por `porcao_base` |
| `ingrediente_receita` | Associativa receita x ingrediente (quantidade e unidade) |
| `comentario`, `favorito` | Interação do usuário |

## 3. Mudanças do MySQL para o PostgreSQL

| MySQL | PostgreSQL |
|---|---|
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` |
| `ENUM(...)` | `VARCHAR` + `CHECK` (igual aos enums Java) |
| `DATETIME` | `TIMESTAMPTZ` (Java usa `Instant`, em UTC) |
| `TINYINT(1)` | `BOOLEAN` |
| `ON UPDATE CURRENT_TIMESTAMP` | Gatilho `set_atualizado_em()` |
| `UNIQUE` sem caixa (collation) | Índice único em `lower(coluna)` |

Valor novo em enum Java exige **alterar o `CHECK`** no SQL.

## 4. Pontos importantes

- **Busca sem acento:** extensão `unaccent`. "acucar" encontra "Açúcar".
- **`ON DELETE CASCADE`:** apagar uma receita apaga etapas, dicas e ingredientes dela.
- **`role` de `profissional`** não é garantido pelo banco: o service mantém coerente.
- **`status_verificacao`** de nutricionista nunca vem da API. Quem se cadastra já nasce aprovado; só a equipe esconde alguém (REJEITADO) direto no banco.
- **Email e username** únicos sem diferenciar maiúscula.
- **Comentários nos SQLs** usam legenda: `[DOC]`, `[PROPOSTA]`, `[AJUSTE]`, `[ADIÇÃO]`.

### Comentários e favoritos

- **`comentario`**: texto (até 2000), `nota` e `foto` opcionais. Leitura pública; só o autor edita ou apaga (`404` se não existe, `403` se é de outra pessoa). Apagar a conta ou a receita apaga os comentários (`CASCADE`).
- **`favorito`**: `UNIQUE (id_usuario, id_receita)`. O `FavoritoService` é idempotente: favoritar duas vezes não dá erro, e o `UNIQUE` cobre a corrida entre dois pedidos simultâneos. Fica de propósito **sem** `@Transactional`.

## 5. Conexão da API

Configurada em `application.properties` por variáveis de ambiente (`DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, no `.env`, que não vai para o GitHub).

- Pool do Hikari limitado a **5** conexões (plano grátis do Supabase e equipe inteira no mesmo banco).
- `ddl-auto=validate`: o Hibernate só confere.
- `time_zone=UTC`.

## 6. Erros comuns

- Rodar a API sem `DB_PASSWORD` (não tem valor padrão).
- Alterar a entidade sem alterar o SQL.
- Esgotar conexões do Supabase com pool grande.
- Commitar o `.env`.
